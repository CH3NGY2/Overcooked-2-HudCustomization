# 局内 HUD 编辑器

2026-11-18 开发实现。公开的 v0.1.0 Release 尚未更新；本轮测试只临时部署并恢复启动前的插件，没有执行永久安装。后续观察到游戏与安装文件由外部更新，安装状态须以当前文件为准。

## 进入与保存

1. 安装本轮构建的 `OC2HudCustomization.dll` 和 **ModSettings 1.1.1 或更新版本**，重新启动游戏。
2. 在没有远程玩家的本地普通厨房，打开 ModSettings → HUD 自定义，打开总开关，点击其下方的“进入 HUD 编辑模式”。入口关闭设置页，再取得原生暂停和输入占用。
3. 点击面板里的类别按钮，一次完成选中、高亮和临时预览。随后拖动该类 HUD 主体移动，四边分别改宽高，四角等比缩放；也能通过滑块或数值框调整。
4. 拖动蓝色标题栏可以移动整个面板，移到屏幕边缘时自动限制在屏内；本进程再次打开时保留位置，不新增配置文件项。
5. 按 **反引号 `** 或点击“保存并退出”提交并恢复画面；“取消修改”丢弃本次草稿。普通字母、鼠标松开和其他键不触发保存；该次反引号不会重新打开 ModSettings。无效数字显示红色并阻止保存，写盘失败时也保留编辑状态。

编辑器借用原生 Main/UI/Camera 暂停层、玩家/UI 输入 suppressor 和鼠标占用，不修改 `Time.timeScale`。场景离开、加载、总开关关闭、远端加入或异常会丢弃草稿，释放自己的占用；不会清除其他菜单已有的暂停。

菜谱展示在编辑期间使用独立的非缩放时钟：原生卡片继续展开，修改大小、每行数量和间距后会平滑重新排列；关卡倒计时、订单寿命及世界业务继续暂停。其他菜单取得暂停时，菜谱预览也停止；退出先恢复菜谱 Animator，再释放本编辑器的暂停。

## 原生外观与统一类别选择

面板使用游戏 GameOptions 的纸面、标题条、按钮素材及 Body_Font / Header_Font，以独立 uGUI Canvas 显示。字体按 bundle22 及依赖资源租约保留，不复制 Unity 2017 动态字体、不改共享材质，不复制整套原生菜单或业务回调。HUD 高亮边框与拉伸手柄继续复用已有绘制和拖动逻辑。

面板提供十类：计分板、倒计时、切菜、烹饪 / 烤串进度、搅拌、烧烤火力 / 热力条、洗碗、灭火，以及菜谱、容器图标。烤串食材的烹饪进度复用“烹饪 / 烤串进度”，炉子的热力条使用独立类别。

- 不再分别操作白名单、类别选择和预览三个控件。点击一个类别后，黄色侧标表示当前类别；当前类别才能鼠标拖动，其他类别不被误选。
- 再次点击当前类别结束预览；切换类别先恢复上一类原显隐及进度。保存、取消、离场或停用也会恢复，不保存预览状态。
- 前八类临时显示本关**已经创建、目前隐藏**的同类 UI，进度使用原生半满显示。烧烤热力条还支持从本关活跃冷炉的真实预制体创建临时显示；其他类别不存在实例时提示当前无实例，仍可预先设置参数。
- 不为不存在的炉具、火灾或搅拌机创建业务对象，也不启用整个停用的游戏父层。
- 不透明度为 0、移出屏幕的类别仍可通过类别按钮调整参数或重置。预览不强行覆盖已设定的不透明度。
- 历史隐藏 `Editable=false` 仍可读取；显式选中该类别会在当前草稿中允许拖动。未选类别的已保存显示参数继续应用。

预览只临时修改原生显示对象及其进度条，不调用 `CookingUIController.SetState` 等会触发声音、完成动画和状态转换的入口。可见性被其他拥有者改动时让权并保留诊断。

冷炉预览只创建跟随原炉子的热力显示，不向炉子加热、不写原生 `m_uiInstance`，切换类别或退出即销毁；恢复正常游戏后仍由原生状态创建业务显示。该冷炉路径尚待真实烧烤关验收，不能把下面的预制体测试当作该路径已通过。

## 参数单位与持久化

同类实例共用相对参数：拖动一条切菜进度条会给其他切菜条增加相同偏移，后创建的实例也会继承；不会把所有进度条堆到一个绝对位置。

| 参数 | 单位与范围 |
| --- | --- |
| X / Y | 屏幕宽/高的百分比，-100%～100%；Y 正值向上 |
| 大小 | 原生显示倍率，0.2～3 |
| 宽度 / 高度 | 原生显示的额外轴向倍率，0.25～4 |
| 不透明度 | 0%～100% |
| Editable（历史隐藏项） | 显式选择类别时在草稿中启用，不再单独显示白名单控件 |

位置使用屏幕 XY；不提供含义不同的世界 Z 偏移，不改变悬浮条跟随的游戏实体。宽高改变目前作用于整组显示，文字、圆形装饰可能随单轴拉伸；四角缩放可保持当前纵横比例。

菜谱类别直接编辑原有的卡片大小、每行数量、行间距和不透明度；容器图标类别直接编辑原有大小、每行数量、空位加号和食材不透明度。列数 0 仍表示原生布局，保留所有历史范围。这里的每行数量是显示排布上限，不是订单或容器业务容量，也不新增固定行数设置。这两类通过参数调整，没有新增直接拖动菜谱或容器图标的功能。

八类各 7 项，共 **56 个隐藏原生 BepInEx ConfigEntry**，位于 `HudEditor.<类别>` 分区，全部 `Browsable=false`，不逐项显示在 ModSettings。原有 9 项可见设置保持原键、类型和默认值，新增的可见入口仍只有一个编辑操作。原有八项显示参数与隐藏几何都先修改草稿，实时预览不修改 ConfigEntry 或磁盘；保存时统一提交一次，取消恢复已保存布局。总开关不进入编辑器草稿。保存失败会回滚内存配置并保留编辑状态。

按钮和编辑器文案跟随游戏的 12 种语言；语言未就绪或未知时使用英文，语言刷新继续复用现有 SDK 通知机制。

### 此前原生面板验收

当前编辑入口限无远程玩家的普通厨房。Horde 不适配；生存模式的独立双计时控制器没有纳入本轮实现。对战双队显示沿用同类相对参数，没有逐队独立配置或完整对战验收。

本轮真实 Unity 验证使用实际 ModSettings 页面入口、原生计分板/倒计时及原生进度显示 fixture。点击/拖动属于脚本事件，未冒充物理鼠标验收；fixture 只建立显示对象，没有修改真实订单或伪造烹饪业务。

- 原生面板实机：**116 项**断言，实际画面及截图 **3840×2160**；包含真实 GraphicRaycaster 按钮命中、原生字体跨场景存活、统一类别、滑块草稿、无效数值、实际保存按钮及原有编辑器回归。
- 面板默认 **470×836 UI 单位**，本次缩放为 2，对应 **940×1672 px**。标题栏实际 drag handler 测得位移 **(-120,+40) UI 单位**，即向左 240 px、向下 80 px，不误拖 HUD；屏内限制和重开也通过。
- 计分板移动 **(+307.2, -259.2) px**；右边宽度 **709.75→851.70 px**；角落缩放后 **936.87×304.37 px**。
- 倒计时移动 **(-268.8, -324) px**；上边调整高度 **222→266.4 px**，底边保持。
- 两条切菜显示同时由原生 anchor Y **0.1→0.2**，对应屏幕向上 **216 px**；退出预览恢复隐藏及原显示进度。
- 同一构建的菜谱回归 **65 项**通过，实际画面 **2560×1440**，包含分阶段入场、单/双列、0.5/1/2 倍、重建与恢复。本轮已有新 cfg，未触发旧版迁移分支，因此与早期 73 项包含迁移的结果数量不同。
